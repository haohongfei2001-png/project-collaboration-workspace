# R1 设计系统与操作边界

## 视觉方向

专业、克制的工作软件界面。中性暖白工作区、浅灰导航、低饱和紫色动作，绿色表示验收、蓝色表示待验收、琥珀色表达依赖和来源异常。图标为本仓库内联 SVG，不使用外部图标库、表情头像或营销插画。

布局以真实工作密度为先：首页用目标、可解释的验收进度、下一步行动、里程碑和来源脉络建立判断。任务和资料使用行布局；方案比较才使用并排成果区。没有为每个对象建立一个大计数卡片。

| 基础要素 | 决策 |
| --- | --- |
| 字体 | 系统字体优先：Inter / system UI / 中文系统字体回退；无远程字体依赖 |
| 页面标题 | 桌面约 28px，手机约 23px，适度字重，不挤压工作区域 |
| 正文 | 任务要求、资料正文和 AI 解释以 14px 为主；紧凑表格、操作 12–14px |
| 辅助信息 | 编号、日期、版本和来源元数据 10–12px；示意成果中的微缩界面按缩略图处理 |
| 分隔 | 1px 细边线，轻背景差异，避免粗描边和高强度阴影 |
| 圆角 | 控件 5–6px，面板 8–10px，模态框 12px |
| 动效 | 侧栏 180–200ms 位移与淡入，交互仅轻量颜色变化；尊重 `prefers-reduced-motion` |
| 布局 | 固定左导航，独立滚动工作区；只有一个右侧上下文面板 |

## 导航与上下文

五个项目主入口是“概览、工作结构、资料库、成果与验收、进展记录”。成员权限和来源连接位于次级区，AI 作为当前项目 / 任务的右侧上下文入口。

任务详情、来源详情、AI 不同时堆成三层右栏。打开引用会切换同一上下文面板。任务来源展示固定版本与当前版本，异常在关联处解释，不让用户另开设置页才知道阻塞原因。

“成果与验收”明确分成三种队列：候选方案决策、任务验收、本轮交付。按钮使用“正式提交候选方案”“确认采用这个版本”“提交验收”“确认验收通过”“确认交付”，避免通用 Done 掩盖语义。

## 可操作范围

| 能力 | R1 实际形态 |
| --- | --- |
| 项目建立 | 目标、名称、交付日期；空白或内置模板；原项目保留且可切换 |
| 工作分解 | 三个初始里程碑、可新增任务和父子关系；独立前置依赖；循环 / 会产生死锁的拆分被拒绝 |
| 责任分配 | 负责人可创建、指派；成员可推进自己的工作；观察者只读 |
| 来源登记 | 可录入虚构资料快照，作为项目内或模拟外部来源；不读真实链接或账号 |
| 来源使用 | 任务关联固定版本、来源快照、历史阅读、版本复核、访问失效占位 |
| 候选成果 | 成员提交具体资料版本；同任务比较、负责人采用，保留备选与决策历史 |
| 验收交付 | 勾选完整条件、选择证据、写结论；领域门槛通过后才改变验收与交付状态 |
| AI 理解 | 对当前事实和可读来源做规则生成，区分事实 / 推断 / 建议，引用可打开 |
| AI 写入 | 固定示例需求的结构化任务草案；完整字段审阅、批准、重新校验、幂等和审计 |
| 同步 | 仅对内置反馈来源模拟 PR 合并、Drive v3 与撤权；手工资料不会被硬套脚本 |
| 角色切换 | 6 个虚构人类身份；两个不同权限 AI 角色；前端演示策略并非生产鉴权 |
| 本地保存 | 项目集合和当前身份保存于浏览器；存储不可用时提示，刷新不会故意重置 |
| 重演 | 只恢复内置示例；保留其他新建项目；负责人可以导出完整虚构状态 |

## 响应式

- 宽屏：左导航约 210–224px；首页主区 + 项目脉络；任务、资料保持表格密度。
- 平板：首页脉络移到下方，保留关键任务、状态和负责人；来源表隐藏次要列。
- 手机：左导航改抽屉，详情和 AI 使用全屏面板，表单适配，方案比较纵向排列。仍使用同一数据模型与操作，不另造一套演示数据。
- 实测通过 `scripts/responsive.html` 的实际 iframe 视口完成，截图和范围见测试记录；这不是对真实 iPhone / Android 触控、键盘或系统字体的完整兼容性认证。

## 可访问性

语义化按钮和表单标签，跳至内容链接、可见焦点、模态框焦点循环、Esc 退出、消息 `aria-live`，状态配有文字与图形而非只靠颜色。`⌘/Ctrl K` 搜索、`⌘/Ctrl J` 项目助手、非输入状态 `N` 新建任务。

本轮做基本键盘与可读性检查，不声称已完成 WCAG 全项认证或读屏软件兼容测试。

## 原型后的优先验证

先验证负责人能否准确找到正式采用版本、区分合并与验收、判断最大阻塞，再决定是否值得开发第二套协作系统。真实服务端权限、来源授权和可靠同步是下一版的底座，不能靠继续增加页面替代。
