## 发现的问题与后续源码修复

### 未配置登录入口

问题：初始化页面知道连接缺失，但设置弹窗仍提供可执行 OAuth 链接。当前受保护部署还会把登录请求规范化到另一个受 SSO 保护的分支域，用户离开工作台后没有得到明确的配置说明。

修复：首页与设置弹窗都要求 `configured && capabilities.github` 才显示登录链接；未就绪时，设置弹窗显示“GitHub 登录待配置”，并保留具体设置缺失项。

源码回归覆盖了未配置时不存在 OAuth 链接，以及配置齐备后登录链接重新出现。这一修复尚未在本报告对应的 `810f209` 部署中复测；不能将本地回归结果写成线上复测通过。

### 长历史补读与工作台记录

作为本轮接线补充，前端现在按后端 `coverage.pendingTasks` 显示“历史补读中 / 还有 N 项来源待补读”，明确当前判断仅覆盖已经读取的证据。工作台自己的 `workspace_record` 显示为“工作台记录”，不再统一标为 GitHub 来源；勾选个人任务不会在前端转成产品验收完成。

这些状态以 API 与 DOM 模拟回归验证，未在缺少数据库与 App 授权的预览上制造虚假项目来展示。

### 后台恢复与个人验证记录
